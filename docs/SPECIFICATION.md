# Course Specification - Summary

Condensed from the official project statement ("Project CelLab", Artificial Intelligence course).
The original PDF is intentionally not kept in the repository.

## Task

Implement a system that lets a user describe a **cellular automaton** - a two-dimensional world
(matrix), a set of objects (cell types) and a set of rules for the evolution of that world.

- The description is given in **natural language** and is **validated** by the system.
- The system simulates a number of future generations (fixed or user-provided) and
  **displays / stores all generations**.
- For the same automaton, the initial world can either be **set manually** or **generated by
  rules**.
- For each known automaton the system answers **at least 3 of these 5 questions**:
  1. What is the state after *N* iterations?
  2. When does the system reach a stable state? (no further changes)
  3. Does a particular configuration ever occur?
  4. How many cells of type *X* exist after *N* iterations?
  5. Does the simulation enter a cycle? (repeating sequence of states)
- A **graphical interface** lets the user enter the text description, set simulation parameters
  (number of generations, initial state, whether intermediate generations are stored) and view the
  intermediate/final states.

## Rules about AI usage

- Development may use any conversational/code-generating assistant(s) and free resources.
- **The final system must not include any calls to online or offline agents.**
- **All interactions with conversational agents must be saved** -> [`PROMPTS.md`](../PROMPTS.md).

## Grading

- Teams of up to 4. Individual scores may differ based on contribution.
- Final version presented in the last laboratory (L14); scores set by comparing solutions.
- **Minimum grade (5)** if at least 2 questions are covered.
- Higher grades for extra functionality, e.g.: all question types; a significant dataset validated
  in a NN/RL experiment; harder automata (e.g. **Rule 30**); own enhancements.
- Submission must include: complete source code; documentation of all AI interactions;
  question/answer sets used for training (if applicable); full installation, configuration and usage
  information.

## Example automata from the statement

| # | Automaton | States | Rule idea | Fits core model? |
| --- | --- | --- | --- | --- |
| 1 | Elementary CA (**Rule 30**) | 0/1, 1D | new cell = lookup of (left, self, right) | Yes (lookup rule, 1D) |
| 2 | Brian's Brain | OFF, FIRING, DYING | FIRING->DYING, DYING->OFF, OFF->FIRING if exactly 2 FIRING neighbours | Yes |
| 3 | Cyclic CA | 0..k-1 | x -> (x+1) mod k if >= threshold neighbours have (x+1) mod k | Yes |
| 4 | Langton's Ant | white/black + ant | agent turns/flips/moves | Stretch (agent) |
| 5 | Forest Fire | EMPTY, TREE, FIRE | FIRE->EMPTY, TREE->FIRE if >= 1 FIRE neighbour (+ optional probabilities p, q) | Yes (+ stochastic) |
| 6 | Sandpile | integer grains | cell >= 4 topples to N/S/E/W | Stretch (numeric) |
| 7 | Traffic (1D road) | car/empty (+velocity) | move forward if free | Stretch |
| 8 | Predator-Prey | EMPTY, RABBIT, FOX | movement, energy | No, out of scope (agents with memory) |
| 9 | Epidemic (SIR) | S, I, R | S->I if >= 2 infected neighbours; I->R | Yes (deterministic variant) |
| 10 | Schelling segregation | A, B, empty | unhappy agents move | No, out of scope |
| 11 | Voter model | A, B | majority of neighbours, ties unchanged | Yes |
| 12 | Crystal growth | EMPTY, CRYSTAL | EMPTY->CRYSTAL if exactly 1 crystal neighbour | Yes |
| 13 | Diffusion / heat | real values | average of von Neumann neighbourhood | Stretch (numeric) |
| 14 | Falling sand | EMPTY, SAND, ROCK, WATER | movement rules | No, out of scope |
| 15 | Artificial ecosystem | EMPTY, GRASS, RABBIT, FOX | energy, reproduction | No, out of scope |

Plus Conway's Game of Life (the classic reference automaton).
